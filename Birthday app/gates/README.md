# Approval Gates

For each gate, the stage owner presents the completed artifact, key assumptions, open decisions, and a recommendation. Work that depends on approval pauses until the user explicitly approves or requests changes.

| Gate | Stage | Evidence required |
|---|---|---|
| 1 | Workflow setup | Proposed structure and staged workflow; approved before framework creation. |
| 2 | Product Definition | Product brief, MVP scope, user stories, acceptance criteria, and resolved/explicitly deferred decisions. |
| 3 | Roadmap | Sequenced scope, milestones, dependencies, risks, and implementation readiness. |
| 4 | Research | Research plan/findings or clearly labeled desk research, source notes, and validated assumptions. |
| 5 | Analysis | Requirements traceability, edge cases, data and technical constraints, and prioritized decisions. |
| 6 | Design | User flows, interaction specification, visual direction, and accessibility decisions. |
| 7 | Validation | Implemented app, execution evidence, QA report, and known issues. |
| 8 | Handover | Standalone release package, README, final QA report, and delivery notes. |
